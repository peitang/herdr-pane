# 安全與發布檢查

## 工具的存取邊界

`herdr-pane` 是 agent 終端選單，不是權限管理服務。選號後接上的終端可接受輸入；只觀看畫面不等於取得唯讀權限。

每位使用者應使用自己的 SSH 憑證。若多個人登入同一遠端帳號，即使使用不同金鑰，登入後仍共享該帳號的權限。不能宣稱只授權某一個 pane，也不能把不同的 named session 當成不同使用者之間的安全隔離。

對需要真正唯讀或細分授權的場景，必須另行設計伺服器端強制限制；不屬於此版選單與新增遠端引導的範圍。

## 連線時的原則

- 保留 SSH 主機身分檢查、驗證與必要互動。
- 不接受來自清單資料的任意 shell 程式；避免 `eval`，正確處理參數與引用。
- 清理顯示文字中的終端控制字元，避免惡意名稱改寫終端畫面。
- 列表與連線使用同一份 profile；連線前再次驗證目標身分。
- 遠端程序 ID 與呼叫端重疊時，使用同次 SSH 連線檢查短暫程序標記；這只是防止自接的核對，不是認證、加密或存取控制。無法核對時拒絕本次連線。
- 標記程序不包含憑證、不保存主機 UUID，正常結束、錯誤或取消均回收。
- 不自動 takeover、安裝、更新或重啟執行中的 server。
- 連線失敗不產生含憑證的完整 debug dump。

## 可以發布的內容

- 不含私有環境設定的程式、測試、需求、設計與驗收條件。
- 使用虛構主機、帳號與路徑的範例。
- 本 repository 的 Mermaid 原稿與重新產生的 SVG。
- 不含私有環境細節的檢查結果摘要。

## 不放進 repository 的內容

- 密碼、token、API key、私鑰、公鑰身分註解、驗證 cookie 或完整授權標頭。
- 真實的內網位址、主機名稱、SSH 設定、Herdr session 快照與執行 log。
- 使用者家目錄、公司專案路徑、私人 email、員工或客戶資料。
- agent 對話紀錄、螢幕截圖、工具輸出、備份與整個工作目錄的壓縮檔。
- 未檢查的 Git 歷史、真實作者 email 或個人設定檔。

## 發布前的兩次檢查

### 第一次：內容與圖表

1. 僅將本次程式、測試、文件與圖表放入受檢目錄。
2. 全文掃描憑證格式、email、網路位址、本機絕對路徑及已知環境識別字。
3. 檢查 SVG 的文字、連結、註解、metadata 與內嵌內容；不可只看可見畫面。
4. 開啟圖表確認實際文字、箭頭、分支與閱讀順序。
5. 由第二位 reviewer 檢查流程與機敏資料，修正後重跑相關檢查。

### 第二次：實際準備上傳的版本

1. 檢查 Git staged 檔名與完整差異，使用明確的檔案範圍加入版本。
2. 掃描準備發布的所有 tracked blobs、commit 訊息與作者欄位。
3. 確認機敏檔案未藏在先前 commit；刪掉最新檔案並不會清除歷史。
4. 使用公開識別名稱及 GitHub noreply email，避免發布私人作者 email。
5. 確認目的 repository、可見性與功能分支；不直接提交到 `main`／`stg`。
6. 上傳後核對遠端 commit 與檔案內容，避免將其他工作目錄一起發布。

### 將私人 repository 改為公開

公開範圍包含所有分支與 tag 可到達的歷史，不能只掃描預設分支或最新版。也要檢查 repository 的描述、議題／PR、release 附件、Actions 紀錄與其他可能帶出環境資料的內容；審查紀錄、原始工具輸出及測試機器設定留在 repository 外。

本專案刻意公開的身分只有 GitHub 擁有者、repository 網址、MIT 著作權署名與提交使用的 GitHub noreply email。掃描這些欄位時逐項核對，不因此排除其他帳號、email 或個人路徑。

確認第二位 reviewer 檢查的是相同 commit 與全部公開歷史，再變更可見性；變更後以未登入方式確認公開首頁、程式、授權及檔案雜湊與受檢版本一致。

自動掃描與人工覆核可以降低洩漏風險，無法證明不存在任何機敏資料。未完成的檢查必須明確標示，不以「零命中」代替所有內容已驗證。
